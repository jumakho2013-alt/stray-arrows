# Аудит проекта Stray Arrows, 2026-05-06 (релиз-день)

## TL;DR

Игра готова к релизу — сегодня уже отправлена в обе сторы. **Среднее по проекту: 6.5/10** (а не 10/10), но это нормальная оценка для соло-проекта на старте. Главные слабости — отсутствие CI, отсутствие тестов и линтера, а также монолитный `index.html` 4000 строк. Безопасность и мобильный UX — на хорошем уровне (8–9/10), а вот доступность (a11y) — 2/10 (но это типично для Canvas-игр и не блокирует App Store/Play). До 10/10 не хватает: автоматизации DevOps, тестов, разбиения монолита, лениво-загружаемых уровней.

**Блокеров для релиза нет.** Всё что ниже — про долгосрочное здоровье кода, не про «срочно чинить».

## Почему не 10/10 — конкретно

### Критические проблемы (must fix перед v2)

1. **Двойная загрузка уровней — `index.html:71` и `:75`**
   `levels-baked.js` (4.5MB) + `handcrafted-levels.js` (3.5MB) грузятся одновременно при старте. На low-end Android холодный старт +3-5 сек. handcrafted нужен только для уровней 1–5 (туториал). **Фикс:** вшить туториальные 5 уровней inline в `index.html` либо грузить лениво.

2. **Service Worker версия не синкается автоматически — `sw.js:5` ↔ `package.json:3`**
   `CACHE_NAME = 'stray-arrows-v1.0.16'` обновляется руками. Если забудешь — после обновления Play/App Store клиенты будут видеть старый кэш недели. **Фикс:** генерировать `CACHE_NAME` из `package.json` в build-скрипте (5 минут работы).

3. **NPM HIGH severities** — `npm audit` показывает 3 dev-only уязвимости: `@xmldom/xmldom` (DoS), `minimatch` (ReDoS), `tar` (path traversal). Все через `@capacitor/assets → @capacitor/cli`. На runtime не влияют, но лучше обновить при следующем апгрейде Capacitor.

### Важные (should fix в течение месяца)

4. **18 пустых `try/catch` блоков в `index.html`** — `:19, :86, :89, :148, :179, :275, :351, :385, :437, :447, :449, :451, :452, :458` и др.
   Молча проглатывают ошибки localStorage, Capacitor API, парсинга. Часть оправдана (offline), но не все. **Фикс:** добавить `console.warn` в catch для отладки в dev (через флаг).

5. **ProGuard выключен — `android/app/build.gradle:46`**
   `minifyEnabled false` → APK больше, обратная разработка проще. Не критично для casual-игры, но включить просто (`true` + проверить `proguard-rules.pro`). **Можно ловить crash после включения** — проверь после билда.

6. **Нет CI/CD совсем**
   Каждый билд — ручной `npm run sync && npx cap open ios/android`. Нет lint-чеков, нет валидации `validate-handcrafted.js` в pre-commit, нет автотестов уровней при бейке. **Фикс:** GitHub Actions с одной job — `npm run build` + `node tools/validate-handcrafted.js`. 30 минут.

7. **Keystore пароль в plaintext локально — `android/keystore.properties`**
   Файл gitignored, но если ноут украдут — упс. **Фикс:** перенести в 1Password / macOS Keychain, тянуть в build-скрипте.

### Желательные (для масштаба и v2)

8. **Монолитный `index.html` 3970 строк** — рефакторинг в модули (audio.js, game.js, ui.js, levels.js) станет неизбежен при росте до 1500 уровней. Сейчас работает, но рефакторинг одной системы трогает весь файл.

9. **215 глобальных переменных** в одном IIFE — обернуть в namespace `SA = {}` либо разбить на классы.

10. **169+ магических чисел** — `390, 844, 50, 150, 500ms` без констант. Объединить в `CONFIG = { canvasWidth: 390, ... }`.

11. **Нет линтера и Prettier** — соло-разработчик может это позволить, но при добавлении второго человека или AI-ассистента — превратится в боль.

12. **Нет TypeScript / jsconfig** — никакого автодополнения по типам, рефакторинг рискован.

13. **Нет юнит-тестов** — `tools/validate-handcrafted.js` валидирует только данные уровней, но не игровую логику (попадание стрелы, расчёт звёзд, AdMob fallback).

14. **AdMob `isTesting:false` захардкожен — `index.html:1171`**
    Нет dev/prod флага. Для QA в браузере без Capacitor код выдаёт награду сразу — но тогда сложнее тестировать реальный flow ad-loading. **Фикс:** `isTesting: localStorage.getItem('ae_debug')==='1'`.

15. **NSUserTrackingUsageDescription generic — `Info.plist:52-53`** — текст «Your data will be used to deliver personalized ads to you» абстрактный. Apple может в будущем потребовать конкретику.

## Сильные стороны (где реально 9-10/10)

- **Документация** — README, STORE_LISTING, privacy-policy, AUDIT-файлы за каждый месяц, комментарии в коде. Лучше многих коммерческих проектов.
- **CSP** — `default-src 'self'` + только нужные внешние домены. Эталонно.
- **Permissions Android** — только `INTERNET`. Никаких CAMERA, LOCATION, READ_CONTACTS.
- **Локализация** — 11 языков (EN, RU, ES, DE, FR, PT, IT, TR, JA + др).
- **Safe area / haptic / status bar** — настроено идеально.
- **Privacy policy** — полная, с контактом, AdMob и IDFA расшифрованы.
- **iPad universal app** — работает, не только iPhone.
- **Звуки lazy-load** — загружаются по требованию, не блокируют старт.
